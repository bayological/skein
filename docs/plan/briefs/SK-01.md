# SK-01: Fact sheet: every command, gate check, config key and mode, sourced

## Objective
Every later task in the docs run cites only `docs/facts/FACTS.md`, the README and the owner
facts (`docs/plan/docs-run.md`, ground rule 1). This task writes that file: one source of truth
for what skein does, extracted from the code at the commit you start from, with every bullet
ending in its source.

No such file exists. The facts live in the 12 command scripts (`commands/*.sh`), the libraries
under `lib/`, `setup`, the templates and `README.md`, and the README and the usage text already
disagree with the code in places: `bin/skein:20-52` leaves out flags, and the config table in
`README.md:79-99` leaves out keys the code reads. `docs/plan/docs-run.md`, "Repository facts",
lists the gaps found so far. FACTS.md records the code.

This task writes one Markdown file and changes nothing else. Where the README or the usage text
disagrees with the code, FACTS.md says so in a "Drift" section; SK-04 fixes the README.

## Hard rules for this task
- **Every line that starts with `- ` ends with a source:** `path:line` or `path:line-line` for a
  file ending `.sh`, `.mjs`, `.md`, `.json`, `.tmpl` or `.yml`; `bin/skein:N`; `setup:N`; or a
  commit hash of seven or more characters. The accept step rejects a top-level bullet without
  one, and a bare filename does not count. Detail that shares its parent's source goes in a
  nested bullet (two spaces, then `- `) or a table.
- **The code wins.** When the README or the usage text says something else, record the code and
  add a Drift bullet that cites both sides.
- **Backticks:** write every command (`skein gate`), flag, gate check name (`clean-tree`), config
  key (`baseBranch`) and environment variable in backticks. The accept step looks for each
  check name and config key inside backticks.
- **Rule 17:** test-integrity and secrets scan this file. Describe test-integrity's tokens in
  words ("the TypeScript pragma that switches off checking for a file", "a focused or skipped
  test call") and the secret patterns by kind ("Stripe secret keys", "a PEM private-key
  header"), citing `lib/gate.mjs:171-219`. Typing one out fails your own gate.
- No em dashes in your own sentences. The invariant exempts `docs/facts/` only so that you can
  quote code verbatim.

## Work
1. Create `docs/facts/FACTS.md`: a title, then one sentence saying what it is and the commit it
   was extracted from (`git rev-parse --short HEAD` when you start).
2. **Install:** prerequisites (`git`, `node`, `jq`, `gh`; the Superset CLI for the Superset
   driver; `codex` for cross-model review, optional), what `./setup` links and where, and
   `--uninstall` (`setup:1-19`, `README.md:32-39`).
3. **Commands:** one subsection per command, in the order of `bin/skein:26-48`. For each: one
   line on what it does, every flag and positional argument from the command's own parsing,
   what it prints (the one JSON line where there is one, `lib/common.sh:84-85`), and every
   condition that makes it refuse or fail. Include `skein brief --new`, `skein gate
   --from-branch` and `--standard-only`, and the positional arguments of `skein watch`.
4. **Gate:** each check in code order (`lib/gate.mjs:27`, `276-285`): what it checks, what makes
   it fail, its source line. Say that monotonic counts sit inside `test-integrity`
   (`lib/gate.mjs:223-229`), that later checks are skipped once an earlier one fails
   (`lib/gate.mjs:282-285`), which checks CI runs (`templates/ci.yml.tmpl:27-32`), and what the
   `SKEIN_GATE_RESULT` line carries (`lib/gate.mjs:287`).
5. **Plan:** the task fields the code reads (`id`, `title`, `type`, `slug`, `brief`, `owned`,
   `deps`, `accept`, `money`, `pii`, `done`, `coordinator`), the plan-level `coordinatorOwned`
   and `alwaysAllowed`, the statuses and the overlap rule (`lib/plan.mjs:38-69`), how a task
   counts as merged (`lib/plan.mjs:47-56`), and the naming rules (`lib/common.sh:65-75`).
6. **Config:** every key of `.skein/config.json` the code reads, each with its default and the
   line that reads it: `version`, `name`, `prefix`, `mode`, `envelope`, `coordinatorEnv`,
   `plan`, `briefs`, `reviews`, `vendor`, `gate`, `baseBranch`, `board`, `driver`, `maxAgents`,
   `install`, `standard`, `e2e`, `invariants`, `monotonic`, `secretPatterns`, `secretAllow`,
   `worker`, `review`, `workerPrompt`, `readyMarker`, `setupScript`, `setupTimeout`,
   `setupFatal`. Then `~/.skein/config.json` (`maxAgents`, `projects`) and the environment
   variables `SKEIN_MAX_AGENTS`, `SKEIN_PROJECT_ID`, `SKEIN_DRIVER`, `SKEIN_BOARD`,
   `SKEIN_USER_CONFIG`, `SKEIN_WORKTREES`, `SKEIN_RUNS`, `SKEIN_STATE_DIR` and `SKEIN_KIT_GIT`.
7. **Boards and drivers:** each board's claim rules and each driver's workspace, agent and host
   rules, with the interface each one implements (`lib/boards/github.sh:6-13`,
   `lib/drivers/superset.sh:6-18`).
8. **Caps, Review, Local mode, Skills:** a short section each, from the files under Read first.
   Name the skills as `/skein-init`, `/skein-brief`, `/skein-coordinate`, `/skein-gate` and
   `/skein-status`.
9. **Drift:** one bullet for each place where the README or the usage text disagrees with the
   code, citing both sides.
10. Run the gate and fix whatever it reports.
