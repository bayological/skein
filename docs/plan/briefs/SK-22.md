# SK-22: A blocked review must not pass for an approving one

## Objective
A cross-model review is the only thing standing between a `money`/`pii` task and a merge.
Today a review that never happened is indistinguishable from one that approved, through three
defects on one path. All three were observed live on 6 Nov 2026 in `onchain-strat-analysis`,
which vendors 0.2.0.

1. **A failed review destroys a real one.** `commands/review.sh:59-60` does
   `cp "$OUT.comment" "$RFILE"` unconditionally in local mode. A reviewer whose sandbox died
   before reading a single file still writes output, so that output lands on top of
   `docs/plan/reviews/<ID>.md`. It overwrote two substantive reviews, which had to be
   recovered with `git checkout --`. One of them was the only copy of a review the previous
   session never committed. PR mode (`:62`) posts an additive comment and loses nothing, so
   this is local mode only.
2. **`skein merge` never reads the verdict.** For a sensitive task it requires only that the
   marker *exist*: `grep -q "<!-- skein-review task=$ID "` on the file (`commands/merge.sh:26-27`)
   or one collaborator comment carrying it (`:34-35`). `templates/review-prompt.md:9` makes the
   envelope's verdict one of `MERGE|FIX FIRST|DO NOT MERGE`, and nothing reads it, so
   `verdict: DO NOT MERGE` satisfies the merge gate exactly as well as `verdict: MERGE`.
3. **The usability probe tests the wrong thing.** `commands/review.sh:18` accepts codex when
   `codex --version` succeeds, but the failure is at exec time. On Ubuntu 24.04 with
   `kernel.apparmor_restrict_unprivileged_userns=1` and a non-setuid `/usr/bin/bwrap`,
   `codex exec --sandbox read-only` dies with
   `bwrap: loopback: Failed RTM_NEWADDR: Operation not permitted` while `--version` still
   exits 0. So `.review.fallbackModel` never triggers, `:48` only warns, `:54` passes because
   the output is non-empty, and `:55` passes because codex's apology does contain
   `REVIEW_DONE`. The operator gets a confident empty `DO NOT MERGE`.

After this task: an inconclusive review never occupies the merge-marker path, a prior review is
never lost, `skein merge` refuses a sensitive task whose latest review does not say `MERGE`
unless the coordinator records an auditable override, and an unusable codex sandbox falls back
to the configured model before spending a review.

**Not in scope.** The AppArmor profile that makes bwrap work is the operator's machine fix, not
skein's. Do not add one, do not weaken a sandbox to `danger-full-access`, and do not touch
`commands/doctor.sh`: SK-20 owns it and is unmerged, so the doctor-side report is its job.

## Hard rules for this task
- **Never weaken a test to get green**, and never widen an existing assertion. The existing
  suite must pass untouched: `node --test tests/*.test.mjs`.
- **Keep both modes working.** Local mode (no `origin`) and PR mode are both live; every
  change below has to say what it does in each. `LOCAL_MODE` is already computed in both files.
- **No new runtime dependency.** POSIX shell, `git`, `jq`, `node` only. No `yq`, no `gh` call
  that a local-mode repo cannot make.
- **Exit codes are contract.** `skein review` exits 0 only when it wrote a conclusive review.
  `skein merge` exits non-zero when it refuses. Tests assert these.
- A reviewer's prose may contain the word "verdict"; only the envelope counts. Parse the
  **last** line matching `^verdict:` and nothing else.

## Work
1. **`lib/common.sh`: `review_verdict <file>`.** Print the last `^verdict:[[:space:]]*` line's
   value, uppercased and trimmed, or nothing when there is none. Pure text, no I/O beyond the
   file.
2. **`lib/common.sh`: `review_inconclusive <file>`.** Exit 0 (true) when the output is not a
   real review: it lacks `REVIEW_DONE`, **or** it matches a sandbox-failure signature —
   `bwrap:`, `RTM_NEWADDR`, `setting up uid map`, `Failed to create` — **and** reports
   `findings: 0`. Two conditions, because a genuine review that merely mentions bwrap in a
   finding must not be discarded.
3. **`lib/common.sh`: `review_agent_usable <agent>`.** For `codex`, require `codex --version`
   **and** that an unprivileged user namespace can actually be created: try
   `bwrap --ro-bind / / --unshare-user true` when `bwrap` exists, else
   `unshare --user --map-root-user true`, both silenced. For any other agent keep the present
   `--version` test. No model call: this must be free and fast. Honour
   `SKEIN_SKIP_SANDBOX_PROBE=1` to force the probe to pass, so tests and a correctly
   sandboxed CI can bypass it.
4. **`commands/review.sh:18`: use the helper.** Replace the `codex --version` condition with
   `review_agent_usable codex`, and make the warning say which check failed — version or
   sandbox — because "codex not usable" sent the last operator looking in the wrong place.
5. **`commands/review.sh:54-63`: an inconclusive review never takes the marker path.** After
   the agent runs, when `review_inconclusive "$OUT"`: write the output to
   `<reviews>/<ID>.inconclusive.md` (local) or leave it at `$OUT` (PR mode, where nothing is
   overwritten anyway), leave `<ID>.md` **untouched**, print what was detected and the
   `--agent claude --model <fallbackModel>` command to retry with, and `die`. Keep `:54`'s
   empty-output check ahead of it.
6. **`commands/review.sh`: preserve the previous round.** When the review *is* conclusive and
   `$RFILE` already exists and is non-empty, copy it to `<reviews>/<ID>.r<N>.md` with the
   lowest free `N` starting at 1 before writing the new one. Say so in the log line. The latest
   review stays at `<ID>.md` so `merge`'s path does not change.
7. **`commands/merge.sh:26-27` (local): require an approving verdict.** Keep the marker check,
   then read `review_verdict "$REVIEW_FILE"`. Refuse unless it is `MERGE`, naming the verdict
   found and the file. No verdict line is also a refusal.
8. **`commands/merge.sh:34-35` (PR): the same, from the comment.** Take the most recent
   collaborator comment carrying the marker, parse its verdict with the same helper, and refuse
   unless it is `MERGE`. One `gh pr view --json comments` call; do not loop.
9. **`--override-review "<reason>"` on `skein merge`.** A reviewer is sometimes wrong, and
   without a sanctioned exit a rejected review deadlocks the task. Add it to the flag parser at
   `commands/merge.sh:13`, refuse an empty or whitespace-only reason, and make it override
   **only** the verdict check — never the marker, the gate, the clean tree or the claim. A money
   task with no review at all must still fail on the marker, override or not. Record it where
   the review lives: append `<!-- skein-review-override task=<ID> by=<me> verdict=<found> -->`
   plus the reason to `<ID>.md` in local mode, or post that as a PR comment. Write that record
   **at the moment the verdict check is overridden, before the gate runs**, so the trace exists
   even when the merge then fails for another reason, and in local mode **commit it**, the way
   line 125 already commits the plan update — otherwise it dirties the tree that the local
   merge requires clean and the first attempt always dies after running the gate. Move the
   `on $BASE` and clean-tree preconditions ahead of the override block. The reason is **data,
   never a verdict**: quote each of its lines before appending, or a reason reading
   `verdict: MERGE` becomes a standing approval that every later plain merge accepts. Refuse a
   reason that is itself a flag. An override that leaves no trace, or that grants more than it
   says, is the defect again in a different shape.
10. **`tests/review-verdict.test.mjs`**, one test per defect plus the override, using
    `sandbox(t)` and `gateRepo`, with a stand-in `codex` and `claude` on `PATH`:
    - a reviewer emitting the bwrap signature with `findings: 0` leaves an existing `<ID>.md`
      **byte-identical**, writes `<ID>.inconclusive.md`, and exits non-zero;
    - a second conclusive review moves the first to `<ID>.r1.md` and leaves the new one at
      `<ID>.md`;
    - `skein merge` on a `money: true` task refuses `DO NOT MERGE`, refuses `FIX FIRST`,
      refuses a review with no verdict line, and proceeds on `MERGE`;
    - `--override-review "reason"` lets `FIX FIRST` merge and leaves the override marker and
      the reason behind, committed and the tree clean; `--override-review ""` and
      `--override-review --no-gate` are both refused; a reason containing `verdict: MERGE`
      does not become a standing approval.
    - **A PR-mode case**, with a stand-in `gh` answering `pr list` and `pr view`: a money task
      whose PR carries no marker comment must fail on the marker, with or without the
      override. `gh` prints a scalar with a trailing newline, so an empty jq result is a
      one-byte file and a `[ -s ]` test on it is true — test the marker, not the size.

## What "done" looks like
`scripts/skein/skein gate SK-22` ends `SKEIN_GATE_RESULT … status=PASS`, with
`node --test tests/*.test.mjs` green including the untouched existing suite. Re-running the
0.2.0 failure by hand — a stand-in codex that prints the bwrap error and `findings: 0` — leaves
the previous review intact and exits non-zero, and a `DO NOT MERGE` review stops
`skein merge` on a money task.
