# SK-13: init: take values from a kept config, refuse contradicting flags

## Objective
`skein init` keeps an existing `.skein/config.json` (`commands/init.sh:68`), yet the name and
prefix it renders with do not come from that config.
- **Where the values come from.** It derives the name, prefix and base from the directory and
  `origin/HEAD` (`commands/init.sh:23-25`). The driver defaults to `superset`
  (`commands/init.sh:14`). The coordinator variable and the envelope come from the derived
  prefix (`commands/init.sh:27`).
- **What it renders with them.** Every template it writes: `AGENTS.md`, and the pre-push hook,
  which it rewrites on every run (`commands/init.sh:123`). The closing summary prints the same
  derived values (`commands/init.sh:137`).
- **The damage.** Every other command reads the kept config instead (`lib/common.sh:40-41`,
  `lib/common.sh:51`). Run plainly over a kept config, init therefore renders an `AGENTS.md`
  whose envelope `skein watch` never waits for, and a hook that checks the wrong coordinator
  variable.
- **The evidence.** SK-11 reproduced this (`docs/plan/briefs/SK-11.md:4-12`), and the run log
  records it (`docs/swarm-run.md:134-138`).

After this task:
- A value not given as a flag comes from the kept config, and init derives only what neither
  supplies.
- A flag that contradicts the kept config is refused before anything is written.
- `--force-templates`, which rewrites the config, lets flags win.
- A repository with no config behaves exactly as today.

Nothing else about init changes: toolchain detection, templates and vendoring stay as they are.

## Hard rules for this task
- **Refuse before writing.** A refused init writes nothing and leaves `git status` empty.
- **Portable shell** (rule 14), bash 3.2:
  - `${!var}` and `printf -v` are fine;
  - no `declare -A` and no `${x,,}`.
- **Sandbox only** (rule 10). Try init only in temp copies of the example, never in this
  repository, and never `./setup` (rule 11).
- **Nothing outside init.** Do not change `cfg`, the templates, or what the other commands
  read.

## Work
1. In `commands/init.sh:14`, start `DRIVER` empty.
2. After `cd "$ROOT"` (line 19), before the board default, add a block that runs only when
   `.skein/config.json` exists. It calls a helper once per flag:

   | Flag | Variable | Config path |
   |---|---|---|
   | `--name` | `NAME` | `.name` |
   | `--prefix` | `PREFIX` | `.prefix` |
   | `--base` | `BASE` | `.baseBranch` |
   | `--board` | `BOARD` | `.board.type` |
   | `--driver` | `DRIVER` | `.driver.type` |

   ```bash
   from_kept() {  # from_kept <flag> <var> <jq-path>
     local given="${!2}" kept; kept="$(cfg "$3")"
     [ -n "$kept" ] || return 0
     if [ -z "$given" ]; then printf -v "$2" '%s' "$kept"
     elif [ "$given" != "$kept" ] && [ -z "$FORCE" ]; then die "$1 $given differs from the kept .skein/config.json ($kept): edit the config, or rerun with --force-templates to rewrite it"; fi
   }
   ```

   Then set `DRIVER` to `superset` if it is still empty. The board default and the local-mode
   refusal (lines 20-22) run after this block, unchanged.
3. Keep lines 23-25 as they are. They now fill only what neither a flag nor the config gave.
4. After line 27, if a config exists and `PREFIX` equals its `.prefix`, take `COORD_ENV` from
   `.coordinatorEnv` and `ENVELOPE` from `.envelope`, each falling back to the derived value.
5. Update the header comment (lines 6-9): a kept config supplies the values flags leave out,
   and a contradicting flag is refused unless `--force-templates`.
6. Write `tests/init.test.mjs`. Each case runs in a `sandbox`, on an `exampleRepo` copy:
   1. Plain `skein init` in a folder named `sandbox-copy`:
      - `AGENTS.md` names `HS_WORKER_DONE` and never `SANDBO_`;
      - the hook names `HS_COORDINATOR`;
      - the summary says `skein init done for hello-swarm (HS-xx tasks, board=none, driver=local, base=main`.
   2. A kept config whose `envelope` is `HELLO_WORKER` and whose `coordinatorEnv` is
      `HELLO_COORD` renders those.
   3. After a committed init, each of `--name x`, `--prefix XX`, `--base trunk`,
      `--board github` and `--driver superset`:
      - exits non-zero;
      - prints `differs from the kept .skein/config.json`, naming the flag and the kept value;
      - leaves `git status --porcelain` empty.
   4. Flags equal to the kept values are accepted.
   5. `--force-templates --prefix XX` rewrites the config:
      - the prefix is `XX`, and the name, board, driver and base are the kept ones;
      - `AGENTS.md` names `XX_WORKER_DONE`.
   6. A repository with no config, in a folder named `widget-app`:
      - the prefix is `WIDGET`;
      - the driver is `superset`;
      - `AGENTS.md` names `WIDGET_WORKER_DONE`.
7. Run `node --test tests/*.test.mjs` and `bash docs/plan/accept/SK-13.sh`, then the gate.
