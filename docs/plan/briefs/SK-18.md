# SK-18: Refuse a config version newer than the kit

## Objective
`skein init` writes `"version": 1` into every `.skein/config.json` (`commands/init.sh:73`), and
nothing reads it (`docs/swarm-run.md:146-147`).
- **The bash commands** take each value they need through `cfg`, with a default
  (`lib/common.sh:23-29`).
- **The gate** parses the file and reads what it knows (`lib/gate.mjs:86`).

A kit given a config written for a later kit therefore runs as if it understood it.
- **The commands** silently use defaults for keys whose meaning changed.
- **The gate** judges work with only the checks it knows, and still says PASS.

After this task, a config whose `version` is newer than this kit understands is refused, with
a message saying so.
- **Missing key:** a config with no `version` key counts as version 1, like every config init
  wrote before the key was read.
- **Malformed version:** a version that is not a whole number is refused too.
- **Unparseable file:** a config that is not valid JSON is refused rather than read as
  defaults.

Three places apply the rule:
- `require_config`, which every running command calls (`lib/common.sh:21`);
- `skein doctor`, which reports the version and flags a bad one;
- the gate, which stops with exit 2, the code it already uses for a config it cannot use
  (`lib/gate.mjs:54`, `:85`).

`skein plan` and `skein init` are unchanged: neither calls `require_config`.

## Hard rules for this task
- **The same rule in both places.** A version is accepted when it is absent, or is a JSON
  number that is a whole number no greater than 1. The messages read the same in bash and in
  the gate:
  - `.skein/config.json is version <v>; this kit understands version 1: upgrade the kit`
  - `.skein/config.json has version <JSON>; this kit understands version 1`
  - `.skein/config.json is not valid JSON`
- **The result line keeps its shape** (rule 15). A refusal in the gate is `die`: exit 2, on
  stderr, with no `SKEIN_GATE_RESULT` line.
- **Portable shell** (rule 14) and **Node built-ins only** (rule 13).

## Work
1. **`lib/common.sh`:** replace `require_config` (line 21) with:

   ```bash
   KIT_CONFIG_VERSION=1   # the config version this kit reads; lib/gate.mjs has the same number
   # config_version_error: why this kit cannot use the config, or nothing. A config with no
   # "version" key is version 1, as every config init wrote before the key was read.
   config_version_error() {
     local v
     v="$(jq -r 'if has("version") then .version else 1 end | if type == "number" and . == floor and . >= 0 then tostring else "invalid " + tojson end' "$CONFIG" 2>/dev/null)" \
       || { echo ".skein/config.json is not valid JSON"; return 0; }
     case "$v" in "invalid "*) echo ".skein/config.json has version ${v#invalid }; this kit understands version $KIT_CONFIG_VERSION"; return 0 ;; esac
     [ "$v" -le "$KIT_CONFIG_VERSION" ] || echo ".skein/config.json is version $v; this kit understands version $KIT_CONFIG_VERSION: upgrade the kit"
   }
   require_config() {
     have_config || die "no .skein/config.json here: run 'skein init' first"
     local e; e="$(config_version_error)"; [ -z "$e" ] || die "$e"
   }
   ```
2. **`commands/doctor.sh`:**
   - line 9's message ends `, driver $DRIVER_TYPE, version $(cfg .version 1))`;
   - after it, add `e="$(config_version_error)"; [ -z "$e" ] || bad "$e"`.
3. **`lib/gate.mjs`:** at line 86, parse inside `try`/`catch` and `die` with the not-valid-JSON
   message. Then add `const CONFIG_VERSION = 1;`, with a comment naming
   `lib/common.sh` `KIT_CONFIG_VERSION`, and apply the rule:
   - a missing `version` is 1;
   - `!Number.isInteger(v) || v < 0` dies with the `has version` message, using
     `JSON.stringify(v)`;
   - `v > CONFIG_VERSION` dies with the `is version` message.

   This must run before `--standard-only` (line 99).
4. **`tests/config-version.test.mjs`,** on an `exampleRepo` copy initialised with
   `--name hello-swarm --prefix HS --board none --driver local`, and on a `gateRepo`:
   1. Version 1, and no `version` key:
      - `brief HS-01 --check` and `status` succeed;
      - the gate runs and prints its result line;
      - doctor's config line contains `version 1`.
   2. Version 2:
      - `brief HS-01 --check`, `status` and `SKEIN_MAX_AGENTS=0 dispatch HS-01` exit non-zero
        with `is version 2; this kit understands version 1`;
      - the gate exits 2 with it and prints no result line;
      - doctor shows it as a problem and exits 1.
   3. `"version": "1"` and `1.5` are refused with `has version`; a file that is not JSON is
      refused with `is not valid JSON`, by both `status` and the gate.
5. **ADR:** write `docs/adr/DRAFT-SK-18-config-version.md`:
   - **context:** the key was written and never read;
   - **decision:** the rule above, and that changing what a config means requires bumping
     `KIT_CONFIG_VERSION`, the gate's `CONFIG_VERSION` and init's literal together, plus a
     migration in `skein upgrade`;
   - **consequences:** an older kit, or an older vendored gate in CI, stops loudly on a newer
     config instead of judging it partly.
6. Run `node --test tests/*.test.mjs` and `bash docs/plan/accept/SK-18.sh`, then the gate.
