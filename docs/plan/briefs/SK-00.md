# SK-00: Kit test harness: tests for the gate's checks and the plan

## Objective
The kit has no tests. The gate (`lib/gate.mjs`) judges every task, yet the only things that
judge the gate are a syntax pass over the kit and one sandbox smoke test (`.skein/config.json`
`standard` and `e2e`, `.superset/run.sh:59-63`). A check could be switched off and every gate
would still pass. The docs run found six kit bugs (`docs/swarm-run.md:131-147`), briefed as
SK-13 to SK-18, and their gates need a suite that can tell a fix from a regression.

This task adds that suite, with Node's built-in test runner and no dependencies (rule 13).
The tests run `lib/gate.mjs` and `lib/plan.mjs` on fixture repositories in temp directories.
The task also adds `tests/helpers.mjs`, whose API the SK-13 to SK-18 tests are written against.
It changes no kit code. Once it merges, the coordinator adds `node --test tests/*.test.mjs` to
`standard`, and every later gate runs the suite.

The accept step checks that the suite tests something. In a copy of the kit, it switches off
sixteen checks one at a time, and the suite must fail on every one
(`docs/plan/accept/SK-00.sh:27-42`).

## Hard rules for this task
- **Behaviour, not text.** Run the gate and the plan on fixtures, and assert on exit codes,
  the `[PASS]`/`[FAIL]`/`[SKIP]` lines, the `SKEIN_GATE_RESULT` line and `--json` output.
  Never read the kit's source: a test that searches `lib/gate.mjs` for text tests nothing.
- **Find the kit from the test file** (`new URL("..", import.meta.url)`). Never use PATH,
  `scripts/skein/` or the current directory. The accept step runs the suite in a
  `git archive` copy with no `.git`, and the suite must test that copy.
- **Sandbox only** (rule 10). Every repository a test makes lives under `os.tmpdir()` and is
  deleted afterwards; nothing touches this repository, a remote, GitHub or Superset. Commits
  pass `-c commit.gpgsign=false` and an invented identity (rule 12).
- **The gate scans your added lines** (rule 17). Build every weakener token and key-shaped
  string at runtime from parts (`join(...)`), never as a literal. No em dash anywhere in
  `tests/`: the `no-em-dash-in-docs` invariant does not except it.
- **Do not pin what SK-13 to SK-18 change:** the default base when `baseBranch` is not
  `main`, which workspaces `skein status` lists, how init treats a kept config, a second task
  id, overlapping dispatches, the config `version`. Fixtures use `main` and `version: 1`.
- **Node built-ins only.** The whole suite finishes in under 20 seconds on a laptop.

## Work
1. In `tests/helpers.mjs`, export exactly this API. Later briefs use these names; document each
   one in a comment.
   - `KIT`: the absolute path of the directory above `tests/`.
   - `sandbox(t)` returns `{ dir, env }`. `dir` is a new temp directory, deleted in
     `t.after`. `env` is `process.env` with these changes:
     - every `SKEIN_*` key and `GITHUB_HEAD_REF` removed;
     - `PATH` led by `dir/bin`, where `gh`, `codex` and `claude` are scripts that exit 1;
     - `SKEIN_WORKTREES` and `SKEIN_RUNS` set under `dir`;
     - `SKEIN_USER_CONFIG` pointing at a file holding `{ "maxAgents": 3 }`;
     - `SKEIN_KIT_GIT=1`.
   - `run(cmd, args, { cwd, env, input })` returns `{ code, stdout, stderr }` and never throws.
   - `git(cwd, ...args)` runs git with gpgsign off and the identity `skein test`
     `<test@localhost>`. It returns stdout, and throws with stderr on failure.
   - `write(dir, files)` writes `{ "relative/path": "content" }`, creating parent directories.
   - `makeRepo(dir, files, { branch = "main" })` runs `git init -b <branch>`, writes the files
     and commits them all.
   - `exampleRepo(dir)` makes a committed copy of `KIT/examples/hello-swarm` on `main`, with no
     remote.
   - `gateRepo(dir, { tasks, config = {}, plan = {}, files = {}, branch = "main" })` makes a
     committed repository on `branch` with:
     - `.skein/config.json`: `{ version: 1, name: "fixture", prefix: "FX", baseBranch: branch,
       standard: ["true"], board: { type: "none" }, driver: { type: "local" }, ...config }`;
     - `docs/plan/wps.json`: `{ ...plan, tasks }`;
     - for each task with a `brief` path, a brief that passes `plan.mjs --check`;
     - `files`.
   - `skein(cwd, env, ...args)` runs `bash KIT/bin/skein`.
   - `plan(cwd, env, ...args)` runs `node KIT/lib/plan.mjs`.
   - `gate(cwd, env, ...args)` runs `node KIT/lib/gate.mjs` and also returns `result`: the
     `SKEIN_GATE_RESULT` line parsed into `{ task, base, status, checks: { name: status } }`,
     or `null`.
   - `fakeWorkspace(env, repoDir, key, name, envelope)` writes what the local driver records
     for a workspace named `name`. With `envelope`, it also writes a run log holding that text
     as one assistant message, the way `docs/plan/accept/lib.sh:48-53` does.
   - `join(...parts)` joins its arguments into one string, for the tokens of rule 17.
2. In `tests/gate.test.mjs`, cover each check with a passing and a failing case. The task runs
   on a branch off `main`. At least:
   - **clean-tree:** an uncommitted file.
   - **boundary:** a file outside `owned`, one under `alwaysAllowed`, and a coordinator-owned
     file inside `owned`, which still fails unless the task has `coordinator: true`.
   - **secrets:** a key-shaped added line, and a committed `.env`.
   - **test-integrity:** a focused test and a skipped test; and a `monotonic` count that falls,
     against one that grows.
   - **invariants:**
     - a matching added line fails;
     - the same line in an `except` file passes;
     - the same text in a comment line passes.
   - **standard, e2e, accept:**
     - `accept: ["false"]` fails, and `["true"]` passes;
     - after a static failure, standard, e2e and accept print `SKIP`, unless `--only` names
       them.
   - **The result line and exit codes:** 0 on PASS, 1 on FAIL, 2 for an unknown flag.
3. In `tests/plan.test.mjs`, cover these cases:
   - **merged:**
     - `done: true`;
     - a subject on `main` ending `(FX-01)`, or `(FX-01) (#12)`;
     - not a subject that only mentions the id.
   - **Waiting on deps,** until the dependency merges.
   - **Overlaps:** `src/**` and `src/a.js` conflict in `--json`; disjoint globs do not.
   - **`--check`:**
     - names a missing section, and an owned glob not listed under "You own";
     - passes a complete brief.
   - **`--dispatchable`:** lists only ready tasks.
4. In `tests/sandbox.test.mjs`, prove the helpers:
   - `exampleRepo`, then `skein init --name hello-swarm --prefix HS --board none --driver local`,
     succeeds, and `skein plan` lists HS-01 to HS-03;
   - after `fakeWorkspace` for `feat: farewell function (HS-01)` with an `HS_WORKER_DONE`
     envelope, `skein status` shows that name as `DONE, awaiting gate`.
5. Run `node --test tests/*.test.mjs` and `bash docs/plan/accept/SK-00.sh`, then the gate.

under each of the sixteen mutations. In your hand-off, give the number of tests and the
suite's run time.
