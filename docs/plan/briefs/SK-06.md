# SK-06: Demo recording: scripted vhs tape and GIF

## Objective
The README has no demo. This task records a 60 to 90 second terminal demo of skein running
`examples/hello-swarm` (SK-05) in a throwaway sandbox: a `vhs` tape anyone can re-record, and
the GIF that SK-04 embeds. In order, it shows:
1. `skein plan`: HS-01 and HS-02 ready, HS-03 waiting;
2. `skein dispatch HS-01` and `skein dispatch HS-02`;
3. `skein status`;
4. `skein gate HS-02` failing with the test-integrity message;
5. the fix (`skein send HS-02 ...`), then the gate passing;
6. `skein merge HS-01` and `skein merge HS-02`, then `skein plan` with HS-03 ready.

The workers are scripted, not live models: a stub `claude` on the sandbox PATH makes each
worker's commits, and the caption says "worker commits scripted for the recording". Nothing
outside `docs/demo/` and `docs/assets/demo.*` changes.

## Hard rules for this task
- **Sandbox only** (rule 10): everything runs in a directory the setup script builds, by default
  `/tmp/skein-demo` (`SKEIN_DEMO_DIR` overrides it): no origin, local mode, board none, driver
  local, no network. Never dispatch against this repo.
- **Nothing personal on screen or in files:** no home path, user name, email address, token or
  real repo. The accept step greps the GIF and `docs/demo/*` for `/home/`, `/Users/`, `@gmail`
  and the word "token" in any case, so that word appears nowhere in `docs/demo/` (the stub emits
  no usage fields). Never show `skein doctor`, which prints absolute tool paths. Export
  `SKEIN_WORKTREES`, `SKEIN_RUNS`, `TMPDIR` and `SKEIN_USER_CONFIG` into the sandbox so no path
  under your home appears; use the prompt `PS1='$ '`.
- **Paths in the tape are relative to the repo root;** the setup script finds the kit from its
  own location (`BASH_SOURCE[0]`), never from a typed absolute path.
- **Unattended commits** (rule 12): the sandbox repo's local config sets `commit.gpgsign false`,
  `user.name "skein demo"` and `user.email demo@localhost`, so skein's own commits work too.
- Writing rules (docs-run.md, rule 3) for the README and captions; no em dashes; rule 17 in
  every file, scripts included.

## Work
1. `docs/demo/setup.sh`, sourced by the tape while hidden: set `KIT` to the repo root and
   `D="${SKEIN_DEMO_DIR:-/tmp/skein-demo}"`; delete and recreate `$D`; copy
   `$KIT/examples/hello-swarm/.` to `$D/repo`; symlink `$D/bin/skein` to `$KIT/bin/skein` and
   `$D/bin/claude` to `$KIT/docs/demo/claude`; export `PATH="$D/bin:$PATH"`,
   `SKEIN_WORKTREES="$D/worktrees"`, `SKEIN_RUNS="$D/runs"`, `TMPDIR="$D/tmp"` and
   `SKEIN_USER_CONFIG="$D/machine.json"` (holding `{"maxAgents": 3}`); in `$D/repo`, `git init -q
   -b main`, set the local config above, commit, run `skein init`, commit again; define
   `wt() { ... }`, printing a task's worktree path from `skein status`'s data or the driver's
   `$SKEIN_RUNS` metadata; `cd "$D/repo"`; `clear`.
2. `docs/demo/claude`, the stub (executable): parse `-p <prompt>` and `--resume <id>`; take the
   task id from the prompt (`worker HS-0N`) or, on resume, from the current branch name; sleep
   two seconds; run `docs/demo/work/<ID>.sh`, or `<ID>-fix.sh` on resume, in the current
   directory; commit with a conventional message; print stream-json lines the local driver can
   read: a `system` `init` line with a `session_id`, an `assistant` text block holding the
   completion envelope from the sandbox's AGENTS.md (`HS_WORKER_DONE`, `task:`, `summary:`,
   `branch:`, `files:`, `checks:`, `handoff:`), then a `result` line. HS-01 and the HS-02 fix
   run `scripts/skein/skein gate <ID>` first and paste its `SKEIN_GATE_RESULT` line into
   `checks:`. HS-02's first round claims done without running it (`checks: not run`): the
   worker's claim is not evidence, and the coordinator's gate catches it.
3. `docs/demo/work/HS-01.sh` adds farewell and its test honestly. `HS-02.sh` makes the change
   and takes the shortcut: it deletes the tests that now fail. `HS-02-fix.sh` restores them with
   updated expected values.
4. `docs/demo/demo.tape`: `Output docs/assets/demo.gif`, a fixed size (start at 1200x700), a
   readable font size, a theme; hidden, `source docs/demo/setup.sh`; then the six steps from the
   Objective with `Sleep`s so the whole tape runs 60 to 90 seconds. Run the gate as the
   coordinator would, `(cd "$(wt HS-02)" && skein gate HS-02)`. After `skein send`, sleep long
   enough for the resumed stub to commit before gating again.
5. `docs/demo/README.md`: what the demo shows, the caption "worker commits scripted for the
   recording", how to re-record (`vhs docs/demo/demo.tape` from the repo root), and that it needs
   `vhs`, `ttyd` and `ffmpeg`.
6. Record with `vhs docs/demo/demo.tape`. Check the size (under 5 MB; lower the frame rate or the
   window size if not) and the duration (`ffprobe -v error -show_entries format=duration -of
   csv=p=0 docs/assets/demo.gif`). Watch it through once, then run the gate.

## What "done" looks like
`scripts/skein/skein gate SK-06` ends `status=PASS`. The GIF shows all six steps, including the
test-integrity failure and the passing gate after the fix, and re-recording from the tape
reproduces it.
