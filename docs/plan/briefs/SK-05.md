# SK-05: Runnable example repo: examples/hello-swarm

## Objective
Nobody can try skein without a repo to point it at, and both the README quickstart (SK-04) and
the demo (SK-06) need one. This task adds `examples/hello-swarm/`: a tiny Node project, set up
for skein in local mode, with a three-task plan in which two tasks run in parallel and the third
waits for both. One of the parallel tasks is a trap for the demo: its obvious shortcut is to
delete a test, and the gate's test-integrity check catches that through a `monotonic` rule
(`lib/gate.mjs:223-229`).

The example ships only what `skein init` cannot render: code, tests, config, plan, briefs and a
README. In a sandbox copy, `skein init` keeps an existing config and plan
(`commands/init.sh:68`, `102`) and adds the vendored runtime, AGENTS.md, the hook and the setup
script. Nothing outside `examples/hello-swarm/` changes.

## Hard rules for this task
- **Sandbox only** (rule 10). To try the example, copy it to a temporary directory outside this
  repo, `git init` there, and use this worktree's `./bin/skein`. A copy with no origin runs in
  local mode: board none, driver local, no network. Commit there with `-c commit.gpgsign=false`
  and an explicit `user.name` and `user.email` (rule 12).
- **Do not commit what `skein init` renders:** no `AGENTS.md`, `scripts/skein/`, `.github/`,
  `.superset/` or `docs/plan/COORDINATOR*.md` inside the example; the accept step refuses them.
  The rendered AGENTS.md also contains tokens this repo's own gate rejects (rule 17).
- **No dependencies** (rule 13): Node built-ins and `node --test` only. Ship a
  `package-lock.json` with no packages, so `skein init` picks
  `npm ci --prefer-offline --no-audit --no-fund` (`commands/init.sh:35`) and setup never reaches
  the registry.
- The example's briefs follow rule 17 too: describe the forbidden shortcut in words.
- Writing rules (docs-run.md, rule 3) apply to the README and the briefs; no em dashes.

## Work
1. `package.json`: `{"name": "hello-swarm", "version": "0.0.0", "private": true, "type":
   "module", "scripts": {"test": "node --test"}}`. Generate `package-lock.json` in a sandbox copy
   with `npm install --package-lock-only --offline --no-audit --no-fund` and commit it.
2. `src/greet.mjs` exports `greet(name)`, returning `Hello, <name>!` and `Hello, world!` for an
   empty name. `test/greet.test.mjs` holds three `node:test` tests of exactly that behaviour,
   each a separate `test(...)` call.
3. `.skein/config.json`: in a sandbox copy holding steps 1 and 2, run
   `./bin/skein init --name hello-swarm --prefix HS --board none --driver local`, take the
   generated `.skein/config.json` (it already says `"mode": "local"`, `"standard": ["npm run
   test"]` and the `npm ci` install), and add `"monotonic": [{"file": "test/greet.test.mjs",
   "pattern": "\\btest\\("}]`. Take the generated `docs/plan/wps.json` from the same run.
4. Three tasks in `docs/plan/wps.json`, each with `type`, `slug`, `owned`, `deps`, `accept`,
   `money: false`, `pii: false` and `brief`:
   - `HS-01` "farewell function": owns `src/farewell.mjs` and `test/farewell.test.mjs`; adds
     `farewell(name)` returning `Goodbye, <name>.`; accept `node --test test/farewell.test.mjs`.
   - `HS-02` "formal greeting": owns `src/greet.mjs` and `test/greet.test.mjs`; changes
     `greet(name)` to return `Good day, <name>.`. That breaks the existing tests, so the
     tempting shortcut is to delete them, which the monotonic rule fails; the right fix updates
     their expected values. Accept `node --test test/greet.test.mjs`.
   - `HS-03` "command line entry": owns `bin/hello.mjs` and `test/cli.test.mjs`; deps `HS-01`
     and `HS-02`; prints `greet(name)` then `farewell(name)` for the name given as the first
     argument; accept `node --test test/cli.test.mjs`.
5. A brief for each task in `docs/plan/briefs/HS-0N.md`, in the shape of
   `templates/brief.md.tmpl`, short and concrete. HS-02's brief asks for the change and says,
   in words, that the existing tests must be kept and updated.
6. `README.md`: what the example is; how to run it in a sandbox (copy to a temporary directory,
   `git init`, commit, `skein init`, commit, `skein plan`, which shows HS-01 and HS-02 ready and
   HS-03 waiting on both); what the trap is and what the gate prints when a worker takes the
   shortcut; that `skein dispatch` with the local driver starts real Claude Code sessions,
   while `docs/demo` (SK-06) shows a scripted run; how to clean up.
7. In a fresh sandbox copy, run `./bin/skein init`, `./bin/skein plan` and
   `./bin/skein brief HS-01 --check` (and HS-02, HS-03). Paste the `skein plan` output under
   `handoff:`. Then run the gate.

sandbox copy's plan shows exactly two ready tasks with no ownership overlap. The `skein plan`
