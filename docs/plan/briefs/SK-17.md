# SK-17: status: list task workspaces only

## Objective
`skein status` lists every workspace the driver knows (`commands/status.sh:15-17`) and takes
each one's task id from the first `<PREFIX>-...` it finds in the name (`commands/status.sh:19`).
- A workspace with no id gets an empty id.
- An empty id makes the envelope test match any `task:` line (`commands/status.sh:24-25`).

In the docs run, the coordinator's own workspace was listed as a worker, "DONE, awaiting
gate", because its terminal showed envelopes it had read (`docs/swarm-run.md:144-145`). A name
that merely mentions an id, like a notes workspace, is read as that task's worker too.

After this task, status lists a workspace only when its name is a task's workspace name, which
`task_ws_name` makes (`lib/common.sh:71-75`) in one of two forms:
- the name contains `(<ID>)` for a task id in the plan, compared without case, which is also
  how `driver_find` finds it (`lib/drivers/local.sh:99`, `lib/drivers/superset.sh:134`);
- or the name is exactly the lowercased id, which `task_ws_name` uses for a task with no
  `type` or `slug` (`lib/common.sh:74`).

The id shown is the plan's own casing. Other workspaces are left out, and one dim line after
the list counts them: `N other workspace(s) here carry no task id`. When no workspace is a
task's, the section prints `none`. The board section, the caps and each worker's state rules
stay as they are.

## Work
1. **The match.** In `commands/status.sh`, before the loop, read the plan's task ids. In the
   loop, replace line 19's id with:
   - the plan id whose `(<id>)` appears in the name, compared without case;
   - or the plan id whose lowercase form is the whole name.

   If neither matches, count the workspace as skipped and `continue` before anything is read
   or printed.
2. **The output.** Print `  none` when no workspace was listed. If any were skipped, print
   `  N other workspace(s) here carry no task id` dim, after the list and before the closing
   line.
3. **The tests.** Write `tests/status.test.mjs`, in a `sandbox`, on an `exampleRepo` copy
   initialised with `--name hello-swarm --prefix HS --board none --driver local`. Every fake
   workspace carries an `HS_WORKER_DONE` envelope for HS-01.
   1. `coordinator notes` is not listed, and the count line says 1.
   2. `notes about hs-01 (draft)` is not listed.
   3. `feat: farewell function (HS-01)` is listed as `DONE, awaiting gate`.
   4. `hs-02`, the fallback name, is listed as HS-02.
   5. With only `coordinator notes`, the section shows `none` and the count line.
   6. With no workspaces at all, it shows `none` and no count line.
4. Run `node --test tests/*.test.mjs` and `bash docs/plan/accept/SK-17.sh`, then the gate.
