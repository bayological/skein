# SK-20: Superset driver: wait on agent state, not the screen

## Objective
The Superset driver learns what a worker is doing by reading its terminal, because it was
written before the Superset CLI reported agent state. `driver_wait_setup` re-reads the setup
terminal every 3 seconds (`lib/drivers/superset.sh:61-72`). `driver_launch` counts the agent
as started when the screen shows `Working`, `Opus`, `esc to interrupt` or similar
(`lib/drivers/superset.sh:106-120`). `skein watch` reads the screen, then sleeps the whole
poll interval, 120 seconds by default, whatever the worker does (`commands/watch.sh:14`,
`:20-46`), so a finished worker waits up to two minutes to be noticed.

Superset CLI 2.0 (`2.0.0` on the owner's machine) reports agent state and blocks on it:
`superset agents wait --until working|settled` (settled: the turn ended or the agent needs
input) and `superset terminals wait --match <regex>`. Its `terminals` and `agents` commands go
to the cloud when the account has cloud workspaces unless given `--local` (`--host` in
`superset agents wait --help`), and nine driver calls pass no `--local`. `superset ws delete`
is gone from its command list but still runs, as an alias of `superset workspaces archive`.

After this task the driver waits on Superset's agent state, passes `--local` on every call that
names a workspace, terminal or project, and refuses, with the fix, a CLI that lacks `agents
wait` or `terminals wait`. `skein watch` answers within seconds of a worker's turn ending, and
`skein doctor` names a CLI that is too old. Unchanged: envelope parsing, `--resume`, every
`SKEIN_WATCH` outcome and exit code, `driver_delete`, the codex trust step
(`lib/drivers/superset.sh:98-105`), `_pretrust_claude`, and dispatch's order: it creates the
workspace, waits for setup and checks the worktree before it launches the agent
(`commands/dispatch.sh:75-93`), so `ws create --agent --prompt` is not used.

## Hard rules for this task
- **Sandbox only** (rule 10). Tests put a stand-in `superset` first on `PATH`. Read-only
  `superset <command> --help` and `superset schema` are fine for checking flags.
- **`HOME` and `SKEIN_STATE_DIR` in the sandbox.** `driver_launch` writes folder trust into
  `$HOME/.claude.json` (`lib/drivers/superset.sh:79-86`) and `skein watch` logs under
  `SKEIN_STATE_DIR` (`commands/watch.sh:15`). `sandbox()` sets neither; your tests set both.
- **No `die` in the CLI check.** `driver_wait_setup` runs in dispatch's own shell
  (`commands/dispatch.sh:78`), where `die` exits before `fail` releases the claim and deletes
  the workspace. The check prints to stderr and returns 1; its callers return 1.
- **Retype only on a missing binary.** An agent slow to reach working (MCP servers starting)
  must not get the launch typed into its prompt.
- **One interface.** Add `driver_wait_turn` to both drivers and to the list at
  `lib/drivers/superset.sh:6-18`; append it to the end of `lib/drivers/local.sh` so the lines
  the docs cite there stay put. Rename or remove nothing.
- **Portable shell** (rule 14), bash 3.2. macOS has no `timeout` command: bound runs in Node.
- **No literal weakener or key tokens in the test** (rule 17): build them with `join`.

3. **Setup.** Replace the loop at lines 65-71 with one `superset terminals wait --local
   --workspace <ws> --terminal <setup> --match "($READY_RE)|($FATAL_RE)" --max-lines 80
   --timeout <secs> --json` (the `grep -E` defaults at lines 26-27 mean the same in
   JavaScript). On a non-zero exit, print today's timeout message and return 1. Otherwise read
   the screen once (`driver_read <ws> <setup> 80`) in today's order: the ready marker returns

4. **Launch.** Replace lines 106-119 with up to two `superset agents wait --local --workspace

   them, retype the launch as lines 116-118 do (with `--local`), only when `driver_read <ws>
   <term> 40` shows `not found in PATH` or `command not found`. Keep line 120's `die`.
5. **`driver_wait_turn <ws> <term> <secs>`**, after `driver_send`. It returns as soon as a turn
   ends, otherwise takes about `secs`, and prints one word:
   - if `agents wait --until settled --timeout 1` succeeds, the agent is at rest: wait
     `--until working --timeout <secs>`, and print `settled` if that fails;
   - then `agents wait --until settled --timeout <time left, at least 1>`: exit 0 prints
     `settled`, an error containing `Timed out` prints `working`, and any other error sleeps
     out the rest of `secs` and prints `gone`, so no caller spins.

   In `lib/drivers/local.sh` a turn is one `claude` process, its pid in `<term>.pid`
   (`lib/drivers/local.sh:56`). Poll every 2 seconds: `settled` as soon as a process seen
   alive has gone, `working` if one is alive at `secs`, `settled` if none ran.
6. **Watch.** Replace `sleep "$EVERY"` (`commands/watch.sh:45`) with `driver_wait_turn` for the
   smaller of `$EVERY` and the time left before the deadline. Leave the loop when none is left,
   exit 1 when the call fails (its message is on stderr), and log its word to `$LOG`. Say in
   the header (lines 2-6) that between reads it waits on the driver. Nothing else changes.
7. **Doctor.** In the `superset` driver branch (`commands/doctor.sh:23-26`), after the project

8. **Tests** in `tests/superset-driver.test.mjs`, with a stand-in `superset` modelled on the
