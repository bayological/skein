# SK-07: Limitations page

## Objective
The README says what skein does and nothing about where it stops. This task writes
`docs/limitations.md`: honest limitations only, each one sourced, and one marker where the owner
adds what still goes wrong in practice. SK-04 summarises the page in the README and links it.

It changes nothing else, and it does not fix anything it finds. A limitation that looks like a
bug goes on the page as a limitation and under `handoff:` as a possible bug.

## Hard rules for this task
- **Sources:** every line starting `- ` ends with a `docs/facts/FACTS.md:N` reference, a
  `README.md:N` reference, or an `[OWNER: ...]` marker. Later tasks cite FACTS.md, the README
  and the owner facts only (ground rule 1). If a limitation needs a fact that FACTS.md lacks,
  leave it off the page and list it under `handoff:` as a FACTS.md gap.
- State each limit plainly, in one or two sentences: no apologies, no roadmap, no workaround
  that FACTS.md does not describe.
- Writing rules (docs-run.md, rule 3); no em dashes. Rule 17: describe the gate's tokens and key
  patterns in words.

## Work
1. Check each candidate against FACTS.md, keep what holds, and word it from FACTS.md:
   - skein needs `git`, `node`, `jq` and `gh`; the Superset driver also needs the Superset CLI
     and its desktop app running;
   - the Superset driver drives only workspaces on the same host;
   - the local driver runs Claude Code only;
   - cross-model review falls back to Claude when `codex` cannot run;
   - local mode never pushes, opens no pull requests and refuses `--no-gate`;
   - caps are counted through the board, and with board none the repo cap counts only what
     this machine runs;
   - ownership overlaps: `skein plan` reports them among ready tasks; say whether
     `skein dispatch` refuses overlapping tasks, from FACTS.md's list of dispatch refusals;
   - the test-integrity and secrets checks match fixed patterns, so they catch only what is on
     their lists, and they read prose as well as code;
   - invariants skip added lines that look like comments;
   - the gate's default base and the plan's merge detection both read `main`, whatever
     `baseBranch` says;
   - claims on the GitHub board are not atomic; a race is settled after the fact.
2. Group the kept bullets under short headings: Requirements, Drivers and boards, The gate,
   Coordination.
3. End with exactly this bullet: `- [OWNER: anything else that still goes wrong in practice, e.g.
   agents stalling, shallow fixes that pass the gate, cost]`.
4. Run the gate.
