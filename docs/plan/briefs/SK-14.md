# SK-14: dispatch, merge, review: refuse a second task id

## Objective
`skein dispatch`, `skein merge` and `skein review` take one task, but their argument loops
assign every bare argument to `TASK`. Given two ids, they silently act on the last one
(`commands/dispatch.sh:12`, `commands/merge.sh:13`, `commands/review.sh:12`). In the docs
run, `skein dispatch` given two ids dispatched only the second (`docs/swarm-run.md:139`).
The gate already refuses a second argument (`lib/gate.mjs:44-45`).

After this task, all three refuse a second bare argument, wherever it appears among the flags,
with the same message: `one task per call: got <first> and <second>`. They exit non-zero
before reading the plan, so nothing is claimed, created or merged. A single id parses exactly
as today. `watch`, `send` and `brief` take positional arguments with other meanings and are
out of scope.

## Hard rules for this task
- **Change only the bare-argument branch** of each loop. Flags, usage lines and everything
  after parsing stay as they are. SK-16 edits `commands/dispatch.sh` after you, so keep the
  diff small.
- **Use `die`,** like the usage error on the next line of each file. A parse error is not a
  dispatch failure and prints no JSON line.
- **Sandbox only** (rule 10). In tests, a machine cap of 0 (`SKEIN_MAX_AGENTS=0`) stops any
  dispatch that gets past parsing at the cap check, before a claim or a workspace.

## Work
1. In each of the three loops, replace `*) TASK="$1"; shift ;;` with:

   ```bash
   *) [ -z "$TASK" ] || die "one task per call: got $TASK and $1"; TASK="$1"; shift ;;
   ```
2. Write `tests/one-task.test.mjs`. Run it in a `sandbox`, on an `exampleRepo` copy initialised
   with `--name hello-swarm --prefix HS --board none --driver local` and committed.
   1. For each of `dispatch`, `merge` and `review`, `HS-01 HS-02`:
      - exits non-zero;
      - prints `one task per call: got HS-01 and HS-02`.
   2. `dispatch HS-01 --model x HS-02` and `review HS-01 --agent claude HS-02` are refused the
      same way.
   3. With a single id, none of the three prints `one task per call`. With `SKEIN_MAX_AGENTS=0`,
      `dispatch HS-01` reaches `machine cap reached`, and `SKEIN_WORKTREES` stays empty.
3. Run `node --test tests/*.test.mjs` and `bash docs/plan/accept/SK-14.sh`, then the gate.
