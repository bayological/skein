# SK-16: dispatch: refuse a task that overlaps one in flight

## Objective
Owned paths are the lock between tasks, but nothing applies that lock at dispatch.
- `skein plan` lists ownership overlaps among ready tasks (`lib/plan.mjs:64-69`).
- `skein dispatch` refuses many things (`commands/dispatch.sh:32-73`), but not a task whose
  owned paths overlap a task already running. Two such tasks run at once, and the second one to
  merge meets a conflict (`docs/swarm-run.md:142-143`).

After this task, `skein dispatch <ID>` refuses when the task overlaps another task that is not
merged and is in flight. The refusal names that task.
- **Overlap** is the plan's existing test, `overlaps()` (`lib/plan.mjs:38-45`).
- **In flight** means one of two things:
  - claimed on the board: `board_owner` is non-empty (`lib/boards/github.sh:98`,
    `lib/boards/superset.sh:46`; always empty for board `none`, `lib/boards/none.sh:7`);
  - or a workspace for it on this machine: `driver_find` is non-empty
    (`lib/drivers/local.sh:99`, `lib/drivers/superset.sh:134`).

A new flag, `--allow-overlap`, skips the check, for a coordinator who knows the overlap is
harmless.

The check runs once, before any claim. Two coordinators dispatching overlapping tasks at the
same moment can both pass it. That stays a known limit, recorded by SK-19, and is not
re-checked after the claim.
