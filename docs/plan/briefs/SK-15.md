# SK-15: Gate and plan: follow the config's baseBranch

## Objective
The config names the base branch (`baseBranch`, written by `commands/init.sh:74`), and the
bash commands follow it. Dispatch, merge and status all read it (`commands/dispatch.sh:21`,
`commands/merge.sh:16`, `commands/status.sh:34`), through `base_ref`, which gives the branch
itself in local mode and `origin/<branch>` otherwise (`lib/common.sh:47`).

The two Node programs ignore it.
- **The gate's default base** is `origin/main` when that reference verifies, and `main`
  otherwise (`lib/gate.mjs:121`).
- **`skein plan`'s record of merges** is `origin/main` when an origin exists, and `main`
  otherwise (`lib/plan.mjs:48`).

A repository whose base branch is `trunk` therefore has its tasks judged against the wrong
branch, and their merges never counted (`docs/swarm-run.md:140-141`).

After this task, both read `baseBranch` from the config, defaulting to `main` when it is
absent:
- the gate defaults to `origin/<baseBranch>` when that verifies, and `<baseBranch>` otherwise;
- the plan reads `origin/<baseBranch>` after a fetch when an origin exists, and
  `<baseBranch>` otherwise.

The gate's `--base` flag still overrides. Nothing else changes, and local mode (`mode: local`
with an origin present) is out of scope.
