# SK-11: Example: pass --name and --prefix to skein init

## Objective
`examples/hello-swarm/README.md` (SK-05) tells readers to run plain `skein init` in a sandbox
made by `mktemp -d`. Without `--name` and `--prefix`, init derives both from the directory name
(`docs/facts/FACTS.md:38`). It keeps the example's `.skein/config.json`, whose prefix is `HS`,
but renders `AGENTS.md` and the pre-push hook from the derived values. The coordinator
reproduced it on `main` at 89e0ac4: in a folder named `tmp.LAsRuS`, `AGENTS.md` tells workers to
end with `TMPLAS_WORKER_DONE` and the hook checks `TMPLAS_COORDINATOR`, while `skein watch`
waits for `HS_WORKER_DONE`. The README's gate walk-through still works; a real dispatch in the
sandbox would never be seen to finish.

This task changes the README's command to `skein init --name hello-swarm --prefix HS` and says
why in one sentence. SK-06 found the problem, and `docs/demo/setup.sh` already passes the flags.
The kit stays as it is: whether init should read the name and prefix from an existing config is
the owner's call (ground rule 2).
