# SK-09: Cross-model fact-check of the docs

## Objective
The docs run's copy was written by workers on one model, from `docs/facts/FACTS.md`. Before the
owner reads the README diff, a different model checks every factual claim against FACTS.md, the
owner facts and the code, and records a verdict for each in a table. You are that reviewer,
dispatched on a different model from the writers. You write one file, the table, and you fix
nothing yourself: the coordinator sends your "wrong" and "unsourced" rows back to SK-04's worker.

What you check:
- `README.md` as it stands on SK-04's branch, which has not merged:
  `git fetch origin docs/readme-upgrade-sk-04`, then `git show FETCH_HEAD:README.md`;
- `docs/limitations.md` and `examples/hello-swarm/README.md` as they stand on `main`;
- anything under `docs/site/` on `main`, if it exists (it will not in this first pass).

## Read first
- `AGENTS.md`, rule 17; `docs/plan/docs-run.md`, all of it: the owner facts and ground rules.
- `docs/facts/FACTS.md`, all of it.
- The files listed above.

## You own
- `docs/plan/reviews/docs-factcheck.md`

Nothing else. This task is marked `coordinator: true` only so that it may write under
`docs/plan/`. Do not edit `README.md` or any other file.

## Hard rules for this task
- **One row per factual claim:** a command, flag, check, default, number, behaviour or owner
  fact. Wording and style are out of scope.
- **Verdicts are exactly `ok`, `wrong` or `unsourced`.** `ok`: FACTS.md, the owner facts or the
  code supports it; cite the line. `wrong`: a source contradicts it; cite it, and the fix column
  gives the correct statement. `unsourced`: nothing supports or contradicts it; the fix column
  says what to cut, or which `[OWNER: ...]` marker to add.
- **FACTS.md can be wrong too.** Check any line that looks doubtful against the code. A claim
  that matches FACTS.md but contradicts the code is `wrong`, and its fix names the FACTS.md line.
- No `|` inside a cell, since it breaks the table. No em dashes. Rule 17: describe tokens in
  words.

## Work
1. Fetch SK-04's branch and read its `README.md`, then read the other files.
2. List every factual claim, file by file, in reading order.
3. Write `docs/plan/reviews/docs-factcheck.md`: a title; one line naming what you reviewed (SK-04's
   branch head and `main`'s head, as short hashes, and your model); then one table with the
   header `| claim | source | verdict | fix |`. Start each claim cell with its file
   (`README.md: ...`), and leave the fix cell empty for an `ok` row.
4. Under the table, give the count of each verdict.
5. Run the gate.

## What "done" looks like
`scripts/skein/skein gate SK-09` ends `status=PASS`. Every factual claim in the three files has
a row, and every `wrong` or `unsourced` row says exactly what to change. Your envelope's
`handoff:` lists the `wrong` rows, so the coordinator can send them to SK-04's worker.

## Acceptance
`scripts/skein/skein gate SK-09`, whose `accept` step runs:
- `test -s docs/plan/reviews/docs-factcheck.md`
- `grep -Eq '^\| *claim *\| *source *\| *verdict *\| *fix *\|' docs/plan/reviews/docs-factcheck.md`
- `awk -F'|' '/^\| *claim *\|/ { t = 1; next } t && /^\| *:?-/ { next } t && /^\|/ { n++; v = $4; f = $5; gsub(/[ \t*]/, "", v); gsub(/[ \t]/, "", f); if (v !~ /^(ok|wrong|unsourced)$/) { print "row " n ": the verdict must be ok, wrong or unsourced: " $0; bad = 1 } else if (v != "ok" && f == "") { print "row " n ": a " v " verdict needs a fix: " $0; bad = 1 }; next } t { t = 0 } END { if (!n) { print "no claim rows under the table header"; bad = 1 }; exit bad }' docs/plan/reviews/docs-factcheck.md`
- `for f in README.md docs/limitations.md examples/hello-swarm/README.md; do grep -qF "$f" docs/plan/reviews/docs-factcheck.md || { echo "the fact-check never names $f"; exit 1; }; done`

Be direct and economical. Do not poll GitHub. Finish with the completion envelope from
`AGENTS.md`.
