# HS-01: farewell function

## Objective
The package has one function, `greet(name)` in `src/greet.mjs`, covered by three tests in
`test/greet.test.mjs`. Nothing says goodbye.

HS-01 adds a second function in a file of its own, so that it can run at the same time as
HS-02 without either task touching the other's files. HS-03 later calls both from a command
line entry point.

This task adds `src/farewell.mjs` and `test/farewell.test.mjs` and changes nothing else. It
does not touch `src/greet.mjs`, which HS-02 owns, and it does not add a command line entry
point, which HS-03 owns.

- `src/greet.mjs` and `test/greet.test.mjs`: the shape to copy, including the export style.
- `docs/plan/wps.json`: the `owned` globs for HS-01, HS-02 and HS-03.

## You own

- `test/farewell.test.mjs`

Nothing else. If a file outside this list seems to need a change, report `BLOCKED` with the
exact change rather than editing it.

## Hard rules for this task
- `src/greet.mjs` and `test/greet.test.mjs` belong to HS-02, which is running now. Editing
  them fails the gate's `boundary` check and would collide at merge.
- No dependencies. Node built-ins and `node --test` only.

## Work
1. `src/farewell.mjs`: export `farewell(name)`, returning `Goodbye, <name>.` with a full stop.
   Give it the same treatment of an empty name as `greet` has, so `farewell("")` returns
   `Goodbye, world.`.
2. `test/farewell.test.mjs`: three `node:test` tests of that behaviour, one per case, in the
   style of `test/greet.test.mjs`.

## What "done" looks like

tests across the two test files.

## Acceptance
